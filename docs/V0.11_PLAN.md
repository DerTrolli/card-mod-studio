# v0.11 "Reach" — cycle plan

**Status:** planned 2026-10-27 (skeptic-reviewed, 19 findings applied) · not started
**Theme:** make the Studio's controls *reach* what users see, in the places
they can't today — the two big numbers HA draws deep inside the gauge and
thermostat, and the two most-starred custom card collections, **Mushroom**
and **Bubble Card**.
**Evidence:** every fact below is either live-probed in the sandbox
(2026-10-27) or checked against its source — see
[`docs/research/2026-10-v0.11.md`](research/2026-10-v0.11.md) (the research
note; cite it, don't re-search). Where something is *not* yet measured, the
plan says so and names the chunk that measures it.

**Roadmap change (owner decision, 2026-10-27):** Mushroom/Bubble support
(roadmap item #10, previously "post-1.0 stretch") moves into v0.11 next to
the Font size unlocks. The roadmap's "most-requested" label for it has no
traceable source (research §2), so a checkpoint after beta.1 confirms
WS2/WS3 before they start (§3, CP1).

## 1. Where we start (measured 2026-10-27)

- **Font size unlock targets still reachable** on HA 2026.10.4 (card-mod
  4.2.1) and HA 2026.10.0b0 (UIX 8.3.1, the beta rig): gauge
  `ha-gauge$ text.value-text` (default 16px in SVG units), thermostat
  `ha-state-control-climate-temperature$ ha-big-number$ .value` (default
  57px). Probed values: gauge 8 and 30px, thermostat 30px — no extremes, no
  older HA yet (research §3.1).
- **Today's Studio on custom cards** shows every module; **24 dead
  controls** across 4 Mushroom cards and Bubble's button (research §3.4).
  Font's size never reaches Mushroom or Bubble text. **Icon Color already
  works on Mushroom** (audit ✅) — don't rewrite what works.
- **What does reach them** (research §3.3, identical on both engines):
  Mushroom classic — `ha-card { --card-primary-*, --icon-size }` and
  `:host { --mush-* }`; Mushroom template (v5, HA tile parts) — the Studio's
  tile companions (`--ha-tile-info-*`) for text; Bubble button —
  `.bubble-name`, `.bubble-button-background` with `!important`. Not yet
  probed: Mushroom accent/threshold colour variables, Bubble icon colour/size
  and border, Mushroom template icon size.
- **Code facts the plan builds on:** the parser already reads a card-level
  `:host` target (`src/parser/state-mapper.ts:423`, `:1541`) and Icon
  Color/Threshold claim from it; the generator emits no `:host`. The dict
  carrier (`DictSource`, `src/types/index.ts:129`) holds only hand-written
  entries, preserved verbatim — it has no notion of a Studio-owned entry.
  Card gating reads `config.type` strings only (`src/utils/card-caps.ts`);
  Bubble needs `card_type` too.
- **Rigs:** card-mod rig HA 2026.9.4, UIX rig HA 2026.9.4 + UIX 8.3.1; both
  scripts default to the floating `:stable` tag (`tools/sandbox/run.sh:12`,
  `run-uix.sh:21-22`). UIX 8.4.0 requires HA ≥ 2026.10.

## 2. Decisions (settled before code; open items name the chunk that closes them)

These win over any chunk's local choice. Changing one means updating this
section first.

**D1 — One write target.** Everything goes to `card_mod:`/`uix:` through
the existing engine detection and dict-form machinery. Bubble's `styles:`
and Mushroom's own options are never written, only preserved
(`applyCardModStyle` keeps unknown sibling keys).

**D2 — Custom-card profiles are data, read through one lookup.** A new
`src/utils/custom-card-profiles.ts` maps a **profile key** — `config.type`,
plus `card_type` for `custom:bubble-card` (`profileKeyOf(config)`) — to:
which modules show, which emitter each module uses (variables on a
selector, or direct selectors), the claim rules for parsing them back, and
the override-conflict rows, preset filtering and click-to-edit mapping. All
gating consumers move from direct `Set` reads to one capabilities lookup
**once** (C2.0); later chunks only add data.

**D3 — Mushroom classic cards use `ha-card { --card-primary-*,
--card-secondary-*, --icon-size, … }`.** Measured working on both engines;
needs no new generator block and keeps Font's `ha-card` anchor. `:host {
--mush-* }` also works, but the generator has no `:host` emitter, and Icon
Color/Threshold already claim `:host` properties (collision risk). Switch
only if C2.1 measures an advantage. (The research does not establish
`--mush-*` as a stable contract; only that the bundle uses 109 such names.)

**D4 — Mushroom template card = tile.** Reuse the tile emitters
(`--ha-tile-info-*`) for Font/text colour. Icon size: **open until C2.1**.

**D5 — Bubble uses direct selectors with `!important`** on the class names
measured in Bubble 3.4.2 (`.bubble-name`, `.bubble-button-background`;
more after C2.1). The selector map is versioned per Bubble major version in
the profile; the audit re-runs on every Bubble release we adopt.

**D6 — Font size unlocks write Studio-owned pierced entries; the carrier
learns ownership (data model closed by C1.0).** Enabling a number size
makes the style dictionary-form: `'.'` = the existing string + the Studio's
entry (`ha-gauge$`, or `ha-state-control-climate-temperature$` →
`ha-big-number$`). Required data model, settled in C1.0 before any code:
- an owned entry lives in its own carrier field with its original index —
  not in `entries` — so key order survives re-saves and Advanced CSS doesn't
  list it;
- the carrier records whether the Studio created the dict form, so turning
  the last owned entry off returns to a plain string **only** for a
  Studio-created dict (a hand-written `{'.': …}` stays a dict);
- the generator returns `{ css, ownedEntries }`; both write paths
  (`studio-state.applyStudioState` and the duplicate in
  `cms-panel._emitConfigChanged`) and the preset strip/restore use it.
The parser claims an entry back only when it is **exactly** the generator's
shape (compared in emitted px). Any other content under that key stays
preserved and read-only, and the size control shows locked with a note —
never merge into hand-written CSS.

**D7 — Unknown `custom:*` cards keep all modules plus a one-line notice**
("Card-Mod Studio doesn't know this custom card yet — some controls may not
reach it; Advanced CSS always works"). Hiding modules without evidence
would be guessing.

**D8 — Pinned versions.** Rig scripts get explicit tags (C0.1): HA
**2026.10.4**, card-mod 4.2.1, **UIX 8.4.0**, Mushroom 5.2.3, Bubble Card
3.4.2. HA 2026.11 (expected Wed 4 Nov 2026) and UIX 9.0 are added as
*extra* rigs, never as silent baseline moves. A newer card release
mid-cycle is adopted only with a fresh audit.

**D9 — Screen budget.** New controls only inside existing modules (number
size is a row in Font). At 390px, opening the Studio on a gauge must still
show the Font header without scrolling; measured by `release_qa`. Removing
a dead control counts as progress.

**D10 — Number size controls.** Gauge: "Number size" as a percentage of the
16px default, emitted as px; thermostat: px (default 57). Ranges are set
from C1.5's extreme probes (no clipping/overflow), not guessed. The parser
compares emitted px, never a recomputed percentage (no float drift).

**D11 — Number size is independent of Font's base size.** It has its own
on/off and state field (`FontModuleState` gains it), so enlarging only the
gauge number never forces a base size/weight onto the card's title.
`fontBlock`/`mapFont` get an entry point that doesn't require
`ha-card font-size`; the Font header switch shows "on" when either part is.

**D12 — Accent on Mushroom: reached or hidden, decided by C2.1's probe.**
Same for Threshold's accent/text colour on Mushroom and every Bubble module
not yet probed.

## 4. How the work runs

The owner's agent guide applies; its parts this plan relies on, inline:

- **Main session writes WS1 and C2.0 itself** (it holds the v0.10 dict-form
  context). Each heavy chunk gets one **Sonnet adversarial reviewer**
  (effort high), up to two repair rounds, then a gated commit.
- **Other chunks:** Sonnet developer → Sonnet reviewer → ≤ 2 repairs → gated
  commit. At most **4 agents at once**; agents never commit or push except
  through one fixed, gated command; the main session pushes after checking
  messages and footers.
- **Every developer prompt** carries §2 (D1–D12) and this checklist: read
  the decisions your items touch (they win); grep every place a changed
  word or pattern appears and change all or none; check every entry point
  to anything you move; never invent a URL, figure or selector — only
  measured ones; run related tests, typecheck and build, then the full
  suite; report each item as fixed, partly, or not done.
- **Reviewers** are told to assume each change is incomplete until shown
  otherwise, cite file:line or a measurement per defect, and that "no
  defects" is an acceptable answer.
- **A batch checker** after each workstream looks for clashes between
  chunks.
- **QA:** scripts first (release_qa, audit, pierce_check); Haiku scouts only
  on the new custom-card screenshots, verified by one Sonnet pass.
- **Owner checkpoints:** spend approval before each workstream; CP1; review
  of each beta before publishing.

**Estimated agent spend** (ratios measured on another project in Oct 2026:
≈ $0.6–1.25 per chunk-sized issue incl. review; ≈ $1 for a decisions
review; Haiku research ≈ $0.04/question): WS1 ≈ $4, WS2 ≈ $8–10, WS3 ≈ $6–8,
WS4 ≈ $2, QA ≈ $5 — **≈ $25–30**. Pilot C1.1's review and re-estimate.

## 5. Definition of done (v0.11.0)

- [ ] G1: `pierce_check.mjs` green on both engines and all supported HA
      versions where the path exists (else the control is hidden there or a
      minimum HA is documented); round-trip, mixed-dict and string↔dict unit
      tests; emitted px compared exactly.
- [ ] G2/G3: audit **0 dead** on every profiled card, both engines, HA
      2026.10.4 and 2026.11; generate → parse → generate stable with
      Advanced CSS empty for every profiled card and engine.
- [ ] G4: notice on unprofiled `custom:*`; D9 budget measured at 390px.
- [ ] No regression on built-in cards (existing audit unchanged: 0 dead).
- [ ] Full live suite, functional check, visual QA green on the default
      theme, both engines.
- [ ] Docs: C1.4 files, wiki Mushroom/Bubble pages, CARD_SUPPORT_MATRIX,
      README, CHANGELOG per beta, ROADMAP.

## 6. Risks

| Risk | Evidence | Mitigation |
|---|---|---|
| Owned-entry data model gets key order or Advanced CSS wrong | The carrier holds only hand-written entries today (`types/index.ts:112-139`) | D6 data model closed in C1.0 with a skeptic, before code; dedicated unit tests in C1.1/C1.2 |
| Number size is a dead control on older HA | The gauge DOM already differs on 2025.9/2026.2 (`div.name` vs `p.title`, `css-generator.ts:566-569`) | C1.5 probes 2025.9/2026.2/2026.6; hide per version or document a minimum |
| Custom cards change internals between releases | Mushroom v5 rebuilt its template card on HA tile parts; the community card-mod guide is stale since Mushroom 4.4.0 | Pinned versions (D8); profiles per major version; audit before adopting a new card release; G4 notice |
| Bubble's own `styles:` fights our rules | Both reach the same parts (research §3.3) | C3.3 measures precedence and documents it; we never write `styles:` |
| Profile plumbing breaks built-in gating | Gating reads type strings in ~8 files | C2.0 changes signatures once, existing audit and suites must stay at 0 dead / green |
| Gauge text scales with the dial | Default 16px is SVG units | D10: percent control, px compared; extremes probed for clipping |
| Floating `:stable` moves the baseline mid-cycle | `run.sh:12`, `run-uix.sh:21` | C0.1 pins tags; new versions only as extra rigs |
