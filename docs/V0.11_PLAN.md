# v0.11 "Reach" — cycle plan

**Status:** draft 2026-10-27 — under skeptic review · not started
**Theme:** make the Studio's controls *reach* what users see, in the places
they can't today — the two big numbers HA draws deep inside the gauge and
thermostat, and the two most-starred custom card collections, **Mushroom**
and **Bubble Card**.
**Evidence:** every fact below is either live-probed in the sandbox
(2026-10-27) or checked against its source — see
[`docs/research/2026-10-v0.11.md`](research/2026-10-v0.11.md) (the research
note; cite it, don't re-search).

---

## 0. Goals and non-goals

| # | Goal | Measured "done" |
|---|---|---|
| G1 | Font size for the **gauge value number** and the **thermostat big number** | Live: size changes the rendered number on both engines; round-trips; Advanced shows nothing extra |
| G2 | **Mushroom** cards: no dead controls; Font / Icon Color / Accent / Threshold reach the visible parts | Module-effect audit: 0 dead on every profiled Mushroom card, both engines |
| G3 | **Bubble Card** (`button`, `separator` first): no dead controls; text, icon and background reachable | Same audit, Bubble types in scope |
| G4 | Unknown `custom:*` cards stop looking fully supported | A one-line notice; no silent dead controls claimed as working |

**Non-goals this cycle** (each with its reason):

- **Writing Bubble's own `styles:` key.** Card-mod/UIX reach Bubble's parts
  (probe §3.3), so one engine model stays; `styles:` is preserved untouched.
  Revisit only if users ask (it has its own JS-template syntax).
- **Bubble pop-ups** — no styled `ha-card` (Bubble's README: its `ha-card`
  example works "except for the pop-ups"); different structure, own cycle.
- **Other custom cards** (button-card, Mini Graph, …) — G4's notice covers
  them; per-card profiles only for cards we probe and audit.
- **UIX Forge / UIX 9 features** — 9.0 is beta and changes nothing in the
  style format (research §1); Forge keys stay preserved as today.
- **Gauge needle / segment styling, thermostat ring** — not requested,
  not probed.

## 1. Where we start (measured 2026-10-27)

- **Font size unlock targets still reachable** on HA 2026.10.4 (card-mod
  4.2.1) and 2026.10.0b0 (UIX 8.3.1): gauge `ha-gauge$ text.value-text`
  (default 16px in SVG units), thermostat
  `ha-state-control-climate-temperature$ ha-big-number$ .value` (default
  57px). Research §3.1.
- **Today's Studio on custom cards** shows every module and has **24 dead
  controls** across 4 Mushroom cards and Bubble's button (research §3.4).
  Font's size never reaches Mushroom or Bubble text.
- **What does reach them** (research §3.3, identical on both engines):
  - Mushroom classic: `:host { --mush-* }` or `ha-card { --card-primary-*, --icon-size }`.
  - Mushroom template (v5, built on HA tile parts): the Studio's existing
    tile companions (`--ha-tile-info-*`) for text; icon size open.
  - Bubble: direct class selectors with `!important`
    (`.bubble-name`, `.bubble-button-background`, `.bubble-main-icon-container`).
- **Engines:** card-mod 4.2.1 still newest stable, #606/#617 open; **UIX
  8.4.0 requires HA ≥ 2026.10** (our UIX rig still runs 8.3.1 on 2026.9);
  UIX 9.0 in beta.

## 2. Decisions (settle before any code — AGENT_GUIDE §4D.1)

These win over any chunk's local choice. Changing one means updating this
section first.

**D1 — One write target.** Everything goes to `card_mod:`/`uix:` through the
existing engine detection and dict-form machinery. Bubble's `styles:` and
Mushroom's own options are never written, only preserved.

**D2 — Custom-card profiles are data.** A new `src/utils/custom-card-profiles.ts`
maps a card type (exact `custom:bubble-card` + `card_type`, or a prefix rule
for `custom:mushroom-*`) to: which modules show, and which *emitter* each
module uses (variables on a given selector, or direct selectors). Card-caps
gating (`card-caps.ts`) consults it for `custom:*` types. No profile ⇒ D7.

**D3 — Mushroom classic cards use Mushroom's public theme variables on
`:host`** (`--mush-card-primary-font-size`, `-color`, `-font-weight`,
`--mush-card-secondary-*`, `--mush-icon-size`, …). Reason: they are
Mushroom's theming contract (the 109 `--mush-*` names), the internal
`--card-primary-*` names are not. Cost: the generator and parser gain a
`:host` block (new, see C2.1). Fallback if `:host` round-trip proves
fragile: `ha-card { --card-primary-* }` (also measured working) — decide in
C2.1 with evidence, update this section.

**D4 — Mushroom template card = tile.** Reuse the tile emitters
(`--ha-tile-info-*`) for Font/text colour; icon size is an open probe (C2.3).

**D5 — Bubble uses direct selectors with `!important`.** Bubble's class
names are its de-facto styling API (its README examples use them). The
selector map is versioned per Bubble major version in the profile; the
module-effect audit re-runs on every Bubble release we adopt.

**D6 — Font size unlocks generate Studio-owned pierced entries.** Enabling
the gauge/thermostat number size turns the style into dictionary form:
`'.'` = the existing string + the Studio's entry (`ha-gauge$`, or
`ha-state-control-climate-temperature$` → `ha-big-number$`). The parser
claims an entry back into Font state **only if it is exactly the generator's
shape**; any other content under that key stays preserved and read-only,
and the size control then shows locked with a note (never merge into
hand-written CSS). Turning the control off and having no other pierced
entries returns the style to plain string form (the v0.10 design,
`docs/V0.10_PLAN.md` §4.1).

**D7 — Unknown `custom:*` cards keep all modules plus a one-line notice**
("Card-Mod Studio doesn't know this custom card yet — some controls may not
reach it; Advanced CSS always works"). Hiding modules without evidence would
be guessing. The notice is a single line, no new panel block (screen budget,
D9).

**D8 — Pinned versions for the cycle:** HA 2026.10.4 (+ 2026.11 beta when
it appears — expected release Wed 4 Nov 2026), card-mod 4.2.1, **UIX
8.4.0** (rigs move to HA 2026.10.4 first, as UIX 8.4 needs it), Mushroom
5.2.3, Bubble Card 3.4.2. A newer card release mid-cycle is adopted only
with a fresh audit.

**D9 — Screen budget.** New controls only inside existing modules (the
gauge/thermostat size is a row in Font). At 390px width, opening the Studio
on a gauge must still show the Font module header without scrolling.
Removing a dead control counts as progress.

**D10 — Gauge size control is a scale, thermostat is px.** The gauge number
is SVG text auto-scaled to the dial, so its control is "Number size: 50–200 %"
of the 16px default (emitted as px); the thermostat's is a px slider (24–96,
default 57).

## 4. How the work runs (AGENT_GUIDE applied)

- **Main session writes WS1 and C2.1 itself** — it holds the v0.10
  dict-form context; an agent would re-derive it. Each such chunk gets one
  **Sonnet adversarial reviewer** (effort high for heavy chunks), then up
  to two repair rounds, then a gated commit (tests + typecheck + build exit
  0).
- **WS2/WS3 remaining chunks:** shape C per chunk — Sonnet developer →
  Sonnet reviewer → ≤ 2 repairs → gated commit; at most 4 agents at once;
  agents never push. Every developer prompt carries this section's D1–D10
  and the AGENT_GUIDE §8 checklist.
- **A batch checker** after each workstream looks for clashes between
  chunks (same thing named two ways, one component changed twice).
- **QA:** stage 0 scripts (release_qa, effect audit) first; Haiku scouts on
  the new custom-card screenshots; findings verified by one Sonnet pass.
- **Owner checkpoints:** approve spend before each workstream; review each
  beta before it is published.

**Estimated agent spend** (ratios from the guide's measurements, not a
budget): WS1 reviewers ~$3, WS2 ~$6–8, WS3 ~$5–7, WS4 ~$2, QA ~$5 —
**≈ $20–25** for the cycle. Pilot WS1's first chunk and re-estimate.

## 5. Definition of done (v0.11.0)

- [ ] G1: `pierce_check.mjs` green on both engines (gauge 8/30px-equivalent
      scale, thermostat 30px); round-trip and mixed-dict unit tests.
- [ ] G2/G3: module-effect audit shows **0 dead** on every profiled card,
      both engines, HA 2026.10.x and 2026.11.
- [ ] G4: notice on unprofiled `custom:*`; no layout regression (D9 measured).
- [ ] Full live suite, functional check, visual QA green (default theme —
      C0.4 enforced) on both engines.
- [ ] No regression on built-in cards (existing audit unchanged: 0 dead).
- [ ] Docs: wiki pages, CARD_SUPPORT_MATRIX, README, CHANGELOG, ROADMAP.

## 6. Risks

| Risk | Evidence | Mitigation |
|---|---|---|
| Custom cards change internals between releases | Mushroom v5 rebuilt its template card on HA tile parts; the community card-mod guide is stale since Mushroom 4.4.0 | Pinned versions (D8); profiles per major version; audit re-run before adopting a new card release; G4 notice when an unknown type appears |
| Bubble's own `styles:` fights our rules | Both work on the same parts (probe §3.3) | C3.3 measures precedence and documents it; we never write `styles:` |
| `:host` blocks round-trip poorly | New in the parser | C2.1 decides with tests; fallback in D3 |
| Gauge SVG text scales with dial size | Default is 16px in SVG units, not screen px | D10 scale control; measured by bbox height, not computed px |
| card-mod stays unmaintained | #606/#617 open | Unchanged recommendation (UIX); both engines tested every chunk |
| UIX 9.0 lands mid-cycle | beta.3 on 2026-10-26; no style changes found yet | Re-check its release notes and docs at each beta; a rig on 9.0 for WS5 if it's final by then |
| HA 2026.11 changes gauge/thermostat internals | None announced (2026.10 notes: no gauge/thermostat changes) | Re-run `pierce_check.mjs` on the 2026.11 beta |
| No traceable demand for Mushroom/Bubble | No issue or forum request found | Ship G1 first; announce beta.2/3 to gather feedback before final |
