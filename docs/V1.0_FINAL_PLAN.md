# v1.0.0 final plan — issue #42, then one full release run

Started 2026-11-22. **1.0.0-beta.2 is published** (2026-11-19), so this is a
new version. The owner asked to fulfil issue #42, then do one extensive run of
testing and user simulations, and release the result as the **full 1.0.0**
(the beta suffix is dropped: the owner said this one is final).

## 1. Issue #42 — "Threshold values – string comparison – again"

> Animation & Visual Filters: Apply when: A value matches, Condition. Would
> also be nice to have this for Background selection. (sjs-1956, on 0.11.0)

### What every condition control offers

| Control | Module | Value matches today | After #42 |
|---|---|---|---|
| Threshold rules | Threshold Colors | numbers + text (beta.2, #41) | unchanged |
| Trigger | Animation | numbers | numbers **+ text** |
| Reacts to (effects) | Visual Filters | numbers | numbers **+ text** |
| Apply when (grayscale) | Visual Filters | — (on / off / another entity) | **value matches: numbers + text** |
| Apply when | Background | — (on / off / another entity) | **value matches: numbers + text** |
| Reacts to (width) | Border & Radius | numbers | numbers **+ text** (same shared control) |
| Reacts to (size) | Icon Color | numbers | numbers **+ text** (same shared control) |
| ON / OFF colours | Icon Color, Accent Color | on/off only | on/off; a hint points to Threshold Colors for colours by a number or text |

Grayscale is in scope: in Visual Filters, "Apply when" *is* grayscale's
control, and the reporter has filed twice for missed spots.

The owner asked (2026-11-22) that every conditional colour or setting offer
numbers and text. Colours by a value already are Threshold Colors (number and
text rules since beta.2); an Icon / Accent "colour by value" would write the
same CSS as a one-rule Threshold and could not be told apart on reopen, so
those two modules point to Threshold Colors instead of duplicating it.

### Design (decided on measurements)

- **Storage shape that older versions survive.** Measured against the
  v1.0.0-beta.2 and v0.11.0 sources: putting text into the existing fields
  (`valueOperator: 'is'`, `valueThreshold: 'heating'`) makes them write
  `| float(0) is heating` — an invalid template, the card's whole style is
  dropped — and `applyWhen: 'value'` makes them write "while OFF" (inverted).
  So:
  - text conditions use **new fields** `valueText` + `valueTextOperator`
    (`is` / `is-not`); the number fields stay unset. Older versions then see
    an incomplete value condition and write the unconditional form;
  - Background and grayscale get an **optional `StyleCondition` field**
    (`condition`, `grayscaleCondition`), with `applyWhen` / `grayscaleWhen`
    left `always`. Older versions ignore the field: the background /
    grayscale applies always (measured: no broken template, no inversion).
- **One spelling.** One comparison builder for Threshold rules, conditions
  and the Animation trigger: `states('x') | float(0) > 5`,
  `states('x') == 'heating'`, attributes `state_attr('x', 'a') | string ==
  '…'` (the #41 spelling). One parser for it.
- **Incomplete = unconditional**, as for every condition today (no entity,
  no text yet).
- **Background vs a one-rule Threshold** write similar Jinja; the else branch
  decides: the card's own look (`''` / `inherit` / `none`) → Background, a
  colour → Threshold. Checked on every corpus style (which modules come out
  enabled must not change).
- **A number typed as text** becomes the number comparison `==` / `!=`
  (as #41's normalizeRule), so no state stores number-like text.
- **Editor:** the shared condition control gets `is` / `is not` next to the
  number operators, a text field that starts from the entity's current
  value, the "right now: …" hint, and text attributes while a text operator
  is chosen. The Animation module's own copy of the value controls moves to
  the shared control. Background and grayscale "Apply when" get "A value
  matches" with the same fields.
- Mushroom / Bubble background (variables), the text-only markdown
  `!important` path and entity-less cards are covered.
- 22 languages for the new texts.

## 2. Open items that block 1.0

*Both resolved 2026-11-22:*
- *2025.9 reopen: also fails with the Studio's file blocked and never with a
  1.5 s pause after Cancel — HA 2025.9 ignores an Edit click right after its

  harness (seen without opening the Studio panel and with beta.1 too). Not
  yet measured with the Studio's file blocked. 2025.9 is the declared

- **12 UNSTABLE continuity cases** (Mushroom chips / title cards): a second
  save differs from the first. Same as the baseline, but never read. Find
  out what changes and fix or explain.

## 3. UI / UX review (before the release run, the owner's request)

A lot was added since 0.11. Screenshots of every module in its main states
(desktop and 390px phone, light and dark, a long-word language), reviewed for
consistency, density, labels and discoverability; compared with Home
Assistant's own card editors and popular community editors (e.g. Mushroom's
and Bubble Card's) for patterns worth taking. Small clear fixes are made
directly; anything that reshapes the panel is proposed to the owner first.

## 4. The release run (on one frozen build)

Rules: build once, record the sha256, no source or harness edits during the
run — any fix means rebuild and run everything again. One rig at a time
(parallel runs caused load failures). Every rig's state reset first (profile
language, stored Studio settings, test dashboards). A known-noise allowlist
(the two console messages from HA 2025.9 and 2026.2) is written down; anything
else in the browser console or the HA log fails the run.

1. **Static:** typecheck, lint, the full unit suite, `npm ci` + `vite build`
   gives the same hash, `validate.yml` (HACS + hassfest) green.
2. **Continuity:** styles, rows, configs and presets of every release since
   v0.8.1 (adding v1.0.0-beta.2), the settings fuzz (with text conditions),
   the hand-written fuzz; compared against the v1.0.0-beta.2 source for both
   the CSS and which modules come out enabled.
3. **Rigs × engines:** HA 2026.11 with card-mod, HA 2026.11 with UIX, HA
   2026.2, HA 2025.9: the suite, the functional UI test, and every feature
   check (rename, threshold text, conditions text, beta.2 items, sections,
   phone, readback, languages × 22, presets, containers, features,
   integration).
4. **User simulations** (scripted, through the real UI, real clicks):
   - *Upgrade:* a user on 0.11.0 (the reporter's version), on beta.1 and on
     beta.2 styles cards and saves presets; the bundle is swapped for 1.0.0;
     every card renders the same (computed styles), opens with its controls,
     Cancel changes nothing, a save converts names, presets load.
   - *New user:* first run, language question, styling a tile, entities
     rows, a heading, a section, presets, copy/paste to another card.
   - *The reporter's case:* a climate / vacuum with text states driving
     Animation, Filters, Background and Threshold; the state changes live.
   - *Phone:* the same on a 390px touch viewport.
   - *Keyboard only:* the main flows without a mouse.
   - *Admin:* the integration (add, options, defaults reach the Studio).
   - *Long session:* many edits on many cards, memory and console clean.
5. **Docs:** README (retaken screenshots — the Marketplace shows them —
   status table, cache-bust URL), wiki, CHANGELOG `[1.0.0]`, ROADMAP,
   `package.json` / lockfile / manifest `1.0.0`, "(beta)" labels swept.
