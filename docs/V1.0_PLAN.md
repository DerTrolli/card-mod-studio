# v1.0 plan — languages, the Integrations page, and the v1.0 roadmap items

Started 2026-11-17. Folds into the unreleased **1.0.0-beta.1** (no release
exists for it yet). **Status: built and verified on the rigs** — see the
1.0.0-beta.1 entry in `CHANGELOG.md` for what shipped and how it was checked.
Planned as 0.12; on 2026-11-18 the owner chose to ship it as
**1.0.0-beta.1** instead, since it completes the roadmap's v1.0 items.

## The owner's answers (2026-11-17)

- German text: reviewed by the owner, fine.
- "Settings tab" = **Home Assistant's Integrations page** (Settings → Devices &
  services): a small Python integration with an options dialog.
- Languages: **the ~20 most used**, bundled in the one JS file (about +0.4 MB),
  using **Home Assistant's own terms** in each language (taken from HA's
  translation files). Unreviewed by native speakers; the owner asked for them.
- Scope: languages + settings **and** the v1.0 roadmap items (conditional
  cards, containers nested in containers, per-row styling of nested entities
  cards, tile feature-row styling, preset rename/duplicate/reorder, style
  import/export).
- Priority: the normal desktop browser window first; the phone editor second.

## Languages

English (source), German (done), and: Dutch `nl`, French `fr`, Spanish `es`,
Italian `it`, Polish `pl`, Portuguese `pt`, Brazilian Portuguese `pt-BR`,
Swedish `sv`, Danish `da`, Norwegian Bokmål `nb`, Czech `cs`, Slovak `sk`,
Hungarian `hu`, Finnish `fi`, Russian `ru`, Ukrainian `uk`, Simplified
Chinese `zh-Hans`, Traditional Chinese `zh-Hant`, Japanese `ja`, Korean `ko`.
No right-to-left languages (nothing in the panel is checked for RTL).

Codes: exact match first, then fallbacks (`pt-PT`→`pt`, `zh`/`zh-CN`/`zh-SG`→
`zh-Hans`, `zh-TW`/`zh-HK`→`zh-Hant`, `no`/`nn`→`nb`, `es-419`→`es`, …),
then the base language, else English.

## Order

1. Integration spike: loads, config flow adds an entry, options dialog opens,
   the Studio reads the options — on HA 2026.11 and 2025.9.
2. Language plumbing: codes, per-language grammar checks, glossary tooling.
3. Presets: rename / duplicate / reorder / export / import; card style
   copy & paste (clipboard with a text-field fallback for plain-http HA).
   Storage shape stays readable by 0.11.0.
4. Containers: `conditional` and `entity-filter` (`card:`), containers in
   containers (recursive child sections, events re-emitted per level),
   per-row styling of a nested entities card (verify first — the code may
   already do it).
5. Tile features: probe which selectors change pixels on both engines and the
   older rigs; ship only controls that measure.
6. Integration: finish (options: default language for everyone; default
   ON/OFF colours), config-flow strings in every language, release zip +
   manual install docs.
7. Freeze English, translate everything (glossary from HA's files).
8. Verify (desktop width first, then phone), docs, changelog.

## Precedence of settings

A user's own choice (Studio → ⚙️ Settings, stored per HA user) → the
integration's default (instance-wide, set by an admin) → Auto-detect.

## Distribution of the integration

This repository is a HACS *plugin*; HACS can't install an integration from it.
The integration ships in `custom_components/card_mod_studio/` and as a zip on
the release, with manual install steps. A separate repository for HACS is
the owner's decision (reported).

## What other integrations do (looked at 2026-11-17)

- **UIX 9** (integration + frontend, on our UIX rig): `config_entry_only_config_schema`;
  single entry; options as a **menu** of sub-pages (`async_show_menu`); an
  update listener fires an event and a websocket **subscription** command
  (`uix/connect`, `event_message`) pushes the new options to every open
  browser, so changes apply without a reload; `brand/icon.png` (+ dark and
  @2x) inside the integration — HA 2026.x serves custom-integration icons from
  there (`/api/brands/integration/<domain>/…`); `diagnostics.py`;
  translations `en`, `nl`, `zh-Hans`. It also serves its JS from the
  integration and registers it as a resource.
- **browser_mod**: serves its JS with `async_register_static_paths` and loads it
  with `add_extra_js_url` (one install, no resource to add); registers sidebar
  panels; minimal config flow (create entry straight away).
- **Mushroom** (frontend only, 33 languages): every language bundled statically
  as JSON, looked up by Home Assistant's exact language code
  (`hass.locale.language`, e.g. `pt-BR`, `zh-Hans`), English fallback, ICU
  message format for plurals.

Taken over: subscription push of the options (live update), `brand/` icons,
options menu once there is more than one page, diagnostics, exact language
codes. Not taken over (yet): serving the Studio's JS from the integration —
it would load twice next to a HACS/Marketplace plugin install; noted as a
later option.
