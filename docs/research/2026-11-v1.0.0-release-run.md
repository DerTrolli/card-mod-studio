# v1.0.0 release runs — record (2026-11-22 … 24)

Two full release runs, each on one frozen build, as
`tools/sandbox/harness/release_run.sh` wrote them, followed by the logged
reruns and a note on every line that isn't clean. The rules (freeze, restart
rule, known noise, Home Assistant's log) are in
[`docs/V1.0_FINAL_PLAN.md`](../V1.0_FINAL_PLAN.md) §4; the user-facing
summary is the "Verified" part of the 1.0.0 section in
[`CHANGELOG.md`](../../CHANGELOG.md). Full logs stayed on the build machine.

**Run 1** (2026-11-22 … 23, commit `0fe8449`) passed. A final review followed
— one tester who only looked at the screen and clicked, on all four rigs —
and found a Bubble Card style that didn't show, an empty entity in "A value
matches", Icon Color changing its controls when switched on, Threshold
Colors with no rule showing "Result: Always", and wording (CHANGELOG 1.0.0,
"Fixed"). Those fixes changed `src/` (commit `b8c0ab4`), so by the restart
rule the whole run was repeated on a new frozen build: **run 2**. The file
to release is run 2's. Run 1's record follows run 2's, unchanged apart from
its note on the released file, which run 2 supersedes.

### Notes on the lines that aren't clean

- **cm reporter_case_sim (retried; first attempt 3 of 7)** and **2602
  threshold_text_check (retried; first attempt 3 of 7)** — the style was
  written correctly (the card reopened with it), but the dashboard tile
  showed none of it, in every state. Repeated after the run: the issue #42
  simulation 20 times on the card-mod rig, alone, with every page error
  recorded with its time and the tile's engine element dumped on a miss.
  19 passed; the one that didn't (3 of 7) was the only one with
  `themesReady: Timeout` errors (24 of them, from 30 s after the page
  load): the tile's card-mod element sat in its shadow root with an empty
  style although the card's config held the 552-character style, and it
  stayed so for the whole page, also after the save. card-mod 4.2.1 waits
  for Home Assistant's `hass.themes.theme` before it applies a style and
  gives up after 30 s; on that page load the setting never arrived. The
  Studio neither reads nor sets it (it reads `themes.darkMode` only, and
  dispatches no event Home Assistant acts on apart from the card editor's
  `config-changed`). 200 plain page loads, Studio and no Studio
  alternating: the setting arrived in 0.3 s (median; at most 0.9 s), never
  missing, every tile styled. Known limitation in the CHANGELOG; the
  Troubleshooting FAQ, which said card styles still apply, is corrected.
  The 2602 first attempt also ran while an investigation used the UIX rig
  beside it.
- **cm release_qa dark: 59 of 60** — as in run 1, the one scenario's 11
  errors were all `themesReady: Timeout` (`KNOWN_NOISE`).
  `release_qa.mjs` now counts the list's entries apart (commit `161fe3c`);
  rerun, full dark set: 60 of 60, alongside an investigation on the UIX rig.
- **uix bubble_heal_check: 2 of 3, twice** — on both attempts 1 of 25
  loads showed the Bubble card unstyled with UIX's element in the shadow
  root, nothing misplaced and no repair. See "The Bubble Card repair,
