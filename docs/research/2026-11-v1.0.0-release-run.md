# v1.0.0 release run — record (2026-11-22 … 23)

The record of the 1.0.0 release run on one frozen build, as
`tools/sandbox/harness/release_run.sh` wrote it, followed by the logged
reruns and a note on every line that isn't clean. The rules (freeze, restart
rule, known noise, Home Assistant's log) are in
[`docs/V1.0_FINAL_PLAN.md`](../V1.0_FINAL_PLAN.md) §4; the user-facing
summary is the "Verified" part of the 1.0.0 section in
[`CHANGELOG.md`](../../CHANGELOG.md). Full logs stayed on the build machine.

- **Build:** commit `0fe8449` on `claude/cardmod-feature-request-htidxc`;
  `vite build` twice gave the same file, sha256
  `7d578dcf0a33b9ea61209d10888b0abbdf14ee7b746489697d287c35cc9f886a`
  (1,317,514 bytes), copied out of `dist/` and onto all four rigs; checked
  against that sha256 after the upgrade simulations, at the end, and before
  and after the reruns. Nothing in `src/` changed after the freeze.
- **Rigs:** Home Assistant 2026.11.0 with card-mod 4.2.1 (`cm`), the same
  with UIX 9.0.0 (`uix`), 2026.2.3 with card-mod 4.2.1 (`2602`), 2025.9.4
  with card-mod 3.4.5 (`2509`); Mushroom 5.2.3 and Bubble Card 3.4.3 on the
  2026.11 rigs. One rig at a time; stored presets, palette and settings
  cleared first.
- **GitHub:** the Validate workflow (HACS + hassfest) passed on `0fe8449`.

## Continuity, compared with the 1.0.0-beta.2 baseline

`tools/continuity/run.sh` runs under `set -euo pipefail` (any failing step
fails it); its counters were compared one by one with the accepted
1.0.0-beta.2 run (2026-11-19):

- **Styles** (63,556 cases, 5,835 of them 1.0.0-beta.2's own): the LOST /
  CHANGED / ADDED groups and hits are identical to the baseline; REMAINDER
  has one hit more and UNSTABLE the same 12 (Mushroom chips / title, see
  the plan). The extra REMAINDER hit is a 1.0.0-beta.2 style, and
  1.0.0-beta.2's own code gives the same result for it. 1.0.0-beta.2's styles
  otherwise come out byte-identical (5,804) or with no difference in what
  applies.
- **Rows** 528 of 528 byte-identical; **configs** 935, the same 86
  differing as before (all from older versions).
- **Presets** 10,070, 23 more differing than the baseline — all
  1.0.0-beta.2 presets with an animation the preset filter drops on a card
  that can't use it (Spin on a light card, animations on a heading).
  1.0.0-beta.2's own code gives the same 920 of 943: the sample's generator
  writes the CSS without the filter a preset load applies.
- **Hand-written fuzz** (30,000): identical apart from `ADDED ha-card ::
  transition` 124 → 138. All 14 new cases are a hand-written grayscale on a
  value condition (`filter: {{ 'grayscale(100%)' if states(…) … }}`,
  twice as `FILTER:`), which 1.0's Visual Filters "A value matches" now
  takes over; the module adds its usual `transition: filter 300ms ease`,
  as it already did for ON/OFF grayscale. Which filter applies is unchanged.

build. The asset attached to the v1.0.0 release should hash to that.

## Notes on the lines that aren't clean

- **lint** — the line picked the wrong summary line; the total was
  **180 problems (147 errors, 33 warnings)**, one fewer than before this
  cycle (181). Record only, as planned. (`release_run.sh` now records the
  total.)
- **cm release_qa dark: 59 of 60** — the 11 errors in the one scenario were
  all `themesReady: Timeout waiting for themes to become ready` (card-mod
  waiting for Home Assistant's themes; the first entry of `KNOWN_NOISE`).
  `release_qa.mjs` records raw console errors and doesn't apply the list.
  The scenario alone: clean (rerun line).
- **cm module_effect_audit (built-in)** — the summary didn't make it into
  the line: `DEAD (1): history-graph › threshold:accent-color;
  INCONCLUSIVE (1): gauge › threshold:text-color; HIDDEN-BUT-WORKS (4):
  entities › accent-color, entities › threshold:accent-color, heading ›
  font, heading › font:family`. The history-graph entry is the documented
  line-colour timing (the graph reads a Threshold accent, a template Home
  Assistant renders a moment later, only at its next draw — the wiki's
  Graph-and-Data-Cards page); the same entry is in every audit since the
  0.11.0 release QA (2026-11-12, both engines) and in this cycle's smoke
  run. The gauge text colour is the long-standing inconclusive one (the
  gauge's own animation). **Custom cards** (Mushroom, Bubble Card): 0 dead,
  0 inconclusive on card-mod and on UIX.
- **2602 functional UI: 495 of 496** — the miss is Home Assistant 2026.2
  enabling Save on a mixed-form card whose config is unchanged; the same in
  every release (0.11.0: 470 of 489, the other 18 then being Home
  Assistant's own page-transition errors, now on the known-noise list).
- **2602 / 2509 conditions_text_check 1 of 6, reporter_case_sim 1 of 7** —
  the click driver's entity picker read its search field through
  `ha-input-search`, which only exists from Home Assistant 2026.11, so no
  entity could be picked on 2026.2 / 2025.9 (the functional UI check, with
  its own picker helper, picks entities there in every module). Fixed in
  the harness (commit `b2a47be`): rerun 6 of 6 and 7 of 7 on both, and the
  changed helper still passes on 2026.11 with card-mod and with UIX.
- **2509 functional UI: 488 of 497** — 7 are 2025.9 gaps: 5 Font on tile
  text (Home Assistant added the tile text variables after 2025.9), the
  tile's icon circle not growing with Icon size (`--tile-icon-size` is
  not in 2025.9.4, it is in 2026.2.3: a 36 px icon fills the 36 px circle), and Save on a
  mixed-form card (as on 2026.2). The other 2 were the harness choosing the
  first row of 2025.9's entity list by keyboard before the list had
  filtered (Border "Apply when" got `binary_sensor.movement_backyard`; the
  Studio wrote what was chosen). Fixed in the harness (the row for exactly
  that entity is clicked). The full rerun then had two different misses: "HA's own
  YAML editor is what the user now sees" (seen once in four 2025.9 runs;
  no detail was captured, cause not established) and a dashboard load Home
  Assistant aborted (`net::ERR_ABORTED`) right after a save, which stopped
  the save/cancel section. The three sections alone passed except the
  aborted load, seen again; a retry of that load fixed it (commit
  `282e75c`; 14 of 14 there and on 2026.11). One full run on the final
  harness then measured **490 of 497**: exactly the 7 gaps above.
- **2509 integration_check (retried)** — passed on its retry; the first
  attempt's log was overwritten (`release_run.sh` now keeps it). Alone:
  7 of 7.
- **Home Assistant's logs** — no line names `card_mod_studio`. The errors
  are the harness re-creating an existing test dashboard ("The URL … is
  already in use") and Home Assistant's own outbound requests failing
  certificate checks behind the build machine's proxy.
