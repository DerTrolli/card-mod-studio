# v0.10 "Piercing" — cycle plan

**Drafted:** 2026-08-07 · **Status:** planned (pre-implementation) ·
**Theme:** dictionary-form / `$`-pierce style support — reading, preserving,
and (for verified targets) generating card-mod's shadow-DOM-piercing style
dictionaries, on both engines.

This is roadmap item **#1** (the oldest open correctness item, from the
original compatibility audit §4), plus the features it unblocks: item
**#23** (dict-form entity rows) and two headline styling unlocks that were
documented as "unreachable" in v0.8 — both now **live-verified as
reachable** with pierced selectors (see Feasibility evidence below).

---

## 1. The syntax we're supporting (verified against both engines' docs)

Card-mod and UIX share the same dictionary contract
([card-mod README](https://github.com/thomasloven/lovelace-card-mod),
[UIX DOM navigation](https://uix.lf.technology/concepts/dom/)):

```yaml
card_mod:            # or uix:
  style:             # EITHER a plain CSS string (all we generate today)…
    .: |             # …OR a dict: '.' = styles for the element itself
      ha-card { background: teal; }
    ha-gauge$: |     # key = selector; '$' suffix = enter that element's shadow root
      text.value-text { font-size: 30px !important; }
    ha-state-control-climate-temperature$:   # values recurse: dict-in-dict
      ha-big-number$: |                      # = navigate deeper, step by step
        .value { font-size: 30px !important; }
```

Semantics both engines document identically:
- Non-final selector steps match the **first** element; the final selector
  in a key matches **all** elements.
- Splitting a chain into nested dict levels gives the engine retry points
  for late-rendering elements ("if things seem to be working
  intermittently, split the chain").

**UIX-only extensions — we must PRESERVE but never generate:**
- `$$` express selector (recursive deep shadow search) — UIX-only,
  explicitly not card-mod compatible.
- `&`-prefixed host-filter paths — UIX-only.

These join macros/billets in the "UIX-only features" bucket: recognized,
preserved verbatim, surfaced by the existing reverse-compat warning when
card-mod is the only engine.

**v0.10 generates only the common subset** (dict + `$` + `.` + nested
dicts), so every emitted style stays portable across both engines —
same principle as everything the Studio emits today.

## 2. Feasibility evidence (live-probed 2026-08-07, both engines)

Probed with hand-written dict styles on the sandbox rigs (card-mod 4.2.1
and UIX 8.0.0, both on HA 2026.8.0):

| Target | Path | card-mod | UIX 8 | Verdict |
|---|---|---|---|---|
| **Thermostat big-number size** | `ha-state-control-climate-temperature$` → `ha-big-number$` → `.value { font-size !important }` | ✅ 30px applied | ✅ | **v0.10 unlock** — closes the "hard-coded 57px two shadow roots deep" limitation from v0.8.0-beta.2 |
| **Gauge value-number size** | `ha-gauge$` → `text.value-text { font-size !important }` | ✅ 16px→8px/30px changes rendered height 45→23/86px | ✅ | **v0.10 unlock** — the old "SVG auto-scale makes it fixed" claim only held for the ha-card-variable form, not the pierce |
| Glance icon color | every variant tried: `state-badge$` (with `ha-state-icon`/`:host` rules), chain-split `div.entity →`, plain selector | ❌ inline per-state `style="color:…"` sits on the icon inside the badge's shadow and none of the injected styles landed | ❌ same | **NOT promised.** Stays a documented limitation; optional stretch: probe UIX's `$$` during the cycle as a UIX-only variant, but don't plan around it |

The two unlocks are exactly the two size limitations reported by the
project owner's own v0.8 beta test — high-visibility wins.

## 3. Current code state (audited 2026-08-07, incl. an empirical round-trip probe)

What actually happens to a dict-form style in v0.9.0 today, verified by
running the real pipeline (`parseCardModConfig → mapToStudioState →
generateCss → applyCardModStyle`):

| Input `card_mod.style` | What a save emits today |
|---|---|
| Flat dict (`{"ha-card": "border-radius: 12px;"}`) | **Flattened to string** — semantically close, not byte-identical |
| Pierce key, string value (`{"ha-card $": "h1 { color: purple; }"}`) | **Corrupted** — re-emitted as `ha-card $ { h1 { color: purple;\n}` (unbalanced braces) |
| Nested dict-of-dicts | **`card_mod:` key DELETED entirely** — total silent data loss |
| Dict-form `uix.style` alongside a card-mod-keyed save | **Cleared** by `applyCardModStyle`'s uix-consolidation branch — second, separately-triggered loss path |

Two mitigating facts: damage only fires on the **first user edit** (panel
open never emits), and the row-level guard from v0.7.1
(`studio-state.ts:240` — `typeof resolvedStyle !== 'string' → leave row
untouched`) shows the preserve-verbatim pattern already works.

Key mechanics (file:line):
- `parseDictStyle` (`yaml-parser.ts:112-138`): non-string dict values are
  silently `continue`d (`:117` — the deletion source); string values get
  the naive `` `${selector} { ${decls} }` `` wrap (`:123` — the corruption
  source). No `$` awareness exists anywhere in `css-parser.ts`.
- `applyCardModStyle` (`yaml-generator.ts:83-119`) is the **single write
  choke point** (card, child-card, AND rows all pass through it) and is
  unconditionally string-typed; empty css deletes both keys (`:90-101`).
- `mapAdvanced` (`state-mapper.ts:1611-1621`) re-serializes every
  unclaimed target back to flat `selector { decls }` strings.
- Parse choke point: `parseStyleValue` (`yaml-parser.ts:50`) — every style
  value from every source dispatches here. These two choke points are
  where the tree model plugs in.
- Types that must grow: `CardModConfig.style` / `UixConfig.style` (can't
  express nesting today), `CardModStyleState` (no verbatim-original
  carrier), `EntitiesCardRow.card_mod/uix` (typed `{style: string}` — a
  type-level lie for dict rows), `StyleValue` in `style-compat.ts`.
- Test coverage today: four flat-dict tests, **zero** covering `$` keys or
  nesting at card level, and one (`parser.test.ts:277-290`) that encodes
  the silent-drop as correct and must be rewritten.
- The reverse-compat warning IS dict-aware (`hasStyleContent`), and the
  "Copy to card_mod" fix button already copies dicts **verbatim** —
  existing proof the preserve strategy is viable.

## 3b. Phase 0 — ship a v0.9.1 data-loss hotfix FIRST (before any v0.10 beta) ✅ DONE (2026-08-07)

The two loss paths above are live in the released v0.9.0 for anyone who
hand-writes dict styles. The minimal-diff fix (no tree model needed):

1. Shared `isDictForm(style)` predicate in `style-compat.ts` (lift the
   row guard's `typeof` check).
2. On open: a dict-form card parses as today for *display*, but the panel
   records `sourceForm: 'dict'` + the verbatim original.
3. On save of a dict-form card: **preserve the original dict verbatim**
   (the row-level v0.7.1 strategy lifted to card level) and show the
   banner "this card's styling is written in card-mod's dictionary form —
   the Studio preserves it but can't edit it yet (planned for v0.10)".
   The generic "preserved in Advanced CSS" banner is actively misleading
   for the nested case and must not show instead.
4. Kill the `uix.style`-clearing branch for dict-form uix blocks
   (`usesUixOnlyFeaturesInBlock` doesn't protect dicts today).
5. Regression tests for all four table rows above + a live check opening
   and saving a dict-form card through the REAL panel.

Small, releasable alone, and it makes every v0.10 experiment safe for
real users while the betas run.

## 4. Design

### 4.1 Data model (the core of the cycle)

Extend the parsed-style model from "one CSS string" to "one CSS string per
dict path", keeping today's string-form behavior byte-identical:

- `CardModStyleState` gains `pierced?: PiercedEntry[]` where
  `PiercedEntry = { path: string[]; css: string }` — `path` is the ordered
  list of dict keys (e.g. `['ha-gauge$']` or
  `['ha-state-control-climate-temperature$', 'ha-big-number$']`), `css`
  the leaf string. The existing `targets`/`rawCss` model keeps describing
  the root string (a dict's `.` entry, or the whole style when it's a
  plain string — today's path unchanged).
- **Claiming works per-path**: a module can claim a whole `PiercedEntry`
  (exact path + exactly-parseable css). Unclaimed entries are preserved
  VERBATIM and re-emitted in their original key order — the dict-form
  version of the Advanced-CSS invariant. Nothing is ever reinterpreted.
- **Byte-stability invariant extended**: generate(parse(style)) must
  reproduce a dict style identically — including key order, string vs
  dict-value shape for untouched entries, and string-form styles never
  being converted to dict form unless a pierced feature is enabled.
- **Format migration rule**: a card only switches string→dict when the
  user enables a pierced control (then: previous string becomes the `.`
  entry, new pierced entries appended). Disabling all pierced controls
  collapses back to string form. Both directions round-trip-tested.

### 4.2 Features built on it (in order)

1. **Preservation + read (the safety half, ships first):**
   - Parse dict-form card styles into the model instead of treating them
     as opaque; everything unclaimed is preserved per-path.
   - The panel opens dict-styled cards with all existing modules working
     against the `.` entry (today they see nothing or raw text, per audit).
   - Advanced CSS module: show unclaimed pierced entries read-only as
     `<path> { … }` blocks with a "hand-written shadow-DOM style —
     preserved as-is" hint (editing them visually is NOT in scope).
   - Same for entity-row dict styles (item #23's "invisible to the editor"
     half): parse the row dict's `.` entry into the row controls; pierced
     row entries preserved + surfaced.
2. **Font module: two new per-card companions** (both gated by card type,
   generated as dict entries):
   - Gauge: value-number **size** (`ha-gauge$` entry) — joins the existing
     weight/color support; the size slider stops being hidden on gauge.
   - Thermostat: big-number **size**
     (`ha-state-control-climate-temperature$` → `ha-big-number$`) — same.
   - Both must play correctly with the existing `.title` emitters and the
     Font size round-trip (claimed per-path, exact-match only).
3. **Preview picker follow-up:** the thermostat big number / gauge value
   text already map to Font in the picker — verify the label stays honest
   now that size actually works there (no code change expected, live-check
   assertion added).

### 4.3 Explicitly OUT of scope for v0.10

- Visual editing of arbitrary hand-written pierced styles (read-only
  surfacing only).
- Generating `$$`/`&` (UIX-only) — preserve-only.
- Glance icon color (probed, not achievable — see §2).
- Mushroom/Bubble selectors (item #10) — v0.10 builds the machinery;
  custom-card support is its own later cycle.

## 7. Risks & mitigations

- **Parser-core risk** (highest): the dict model touches the
  claim/re-emit invariant every card depends on. Mitigation: workstream 2
  lands WITH workstream 1 in the same beta; the corpus is written before
  the emitters; beta.1 ships with zero new visible features so the beta
  round isolates round-trip safety.
- **YAML key-order stability**: js-yaml preserves insertion order, but the
  re-emit path must rebuild dicts in original order — corpus asserts it.
- **Engine retry flakiness on pierced paths** (seen with glance): both
  emitted paths are the chain-split form the docs recommend; live checks
  assert with generous polling on both engines.
- **HA renames internal elements** (`ha-big-number` etc.): same class of
  risk as all per-card selectors; covered by the live checks and the
  per-HA-release smoke run (see ROADMAP "Engineering / maintenance").
